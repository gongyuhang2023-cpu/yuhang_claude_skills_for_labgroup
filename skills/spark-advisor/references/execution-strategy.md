# 选择执行地

> 规划时如果任务在本机已经能完成，例如查看小文件或解释现成结果，直接做本地任务。只有执行地或资源有疑问时再比较。

## 用当前任务比较本机与 Spark

1. **输入规模和瓶颈。** 估算实际读入量、峰值内存、GPU 需求、核数和持续时间。用本机当前可用资源衡量，再考虑任务会占用多少日常工作空间。大矩阵、向量化或分支密集任务可能受不同瓶颈限制，必要时用有代表性的小样本估算。
2. **已有环境。** 核对两边是否已有合适版本的工具和依赖、适配的架构和可用的数据库。还需安装或构建时，把准备成本计入。用户指定执行地或任务须操作本机交互界面时，从该约束出发。
3. **数据所在地。** 数据和库已经在某处时，把传输时间、额外副本、落盘空间和接收方纳入比较。优先在资源合适的数据所在地处理。
4. **排队和运行时间。** 把预期排队、环境准备、搬运和运行时间一并考虑。若本机有足够资源、环境和数据均就绪，选定本地后直接完成。若本地有瓶颈，或 Spark 已具备可节省实质成本的环境、库和算力，再按 SKILL.md 读 `rules`，用 `status` 或 `recommend` 核对当时的资源与队列。

选定 Spark 后，按 [提交与监控流程](submit-flow.md) 执行。需要边看结果边改代码时看 [交互调试](debug-session.md)。Spark 的等待成本较高且任务适合外部执行时，可按 [Colab](colab.md) 评估。Spark 跑不动的大批量 CPU 任务，按 [LRZ CoolMUC-4](lrz.md) 评估。LRZ 花课题组经费，只放大任务，先在 Spark 上用小样本跑通、定好资源，速度优先、避免浪费；工具只有 x86 构建时的例外见 lrz.md。CoolMUC-4 没有 GPU，GPU 任务用 Spark。

## 历史示例（2026-07-21）

当时的本机是 i7-265K WSL2（16 核），可用内存约 19.5 GB，且没有适合该任务的 GPU。约 19 GB 是这台机器当时的容量参考。换机器、工作负载或输入后，按上面的步骤重估。下表是当次 Spark GB10（20 核）与该本机的实测，不用来给当前任务分配资源。

| 项 | 当时的本机 | 当时的 Spark |
|---|---|---|
| 内存带宽 | 19.9 GB/s | 29.7 GB/s |
| Tanimoto（真实批量） | 0.177 s | 0.131 s |
| matmul（BLAS） | 643 GFLOPS | 781 GFLOPS |
| RDKit 指纹（单线程） | 10,366 /s | 11,134 /s |
| sklearn RF 拟合 + 预测 | 15.0 s/轮 | 18.3 s/轮 |
| 可用内存 | 19.5 GB | 121.7 GB |

当时批量指纹和 BLAS 受高内存带宽与优化影响，在 Spark 上更快。小规模随机森林的分支密集运算在本机更快。把这些结果当作判断瓶颈的线索，再结合当前的输入、环境和机器。
