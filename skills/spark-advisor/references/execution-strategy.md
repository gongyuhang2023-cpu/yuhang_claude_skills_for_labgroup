# 执行地判定 — 本地还是上服务器？

> 在为一个任务定 slurm 参数**之前**先问：这活到底该在**本地**跑，还是上**共享服务器**？
> 上了服务器不代表更快——ARM 服务器在某些负载上反而慢。判错 = 要么白占公共资源、
> 要么把本可以更快跑完的活拖慢。
>
> ⚠️ **下面的数字是"作者的本地机 vs 这台 Spark"这一组基准**（2026-07-21 实测）。
> 判定**规则**（架构层面）通用；**具体数字**换一台本地机就得重标。

## 默认上服务器 —— 本地机不是空闲资源

本地机的内存和 CPU 被你平时的东西占着（浏览器、编辑器、同步盘、手头正在跑的分析）。一个计算占住它，手头别的事就停了 —— 这个成本不在下面任何一条基准数字里，但它是真的。

所以**计算类的活默认上服务器；留在本地需要正面理由**。下面这张表给的就是那些正面理由，**不是**「先看看本地行不行」的清单。「本地也跑得动」「规模小」不算理由；「本地快 22%」也不够 —— 速度差抵不过占住本地机，只在数据小、几分钟内能完时才成立。

本地该做的是：交互、要看图、编排、小文件读写，以及**运行目标本来就是这台机器**的东西。

## 一句话判据

| 情况 | 去哪 | 为什么 |
|---|---|---|
| 要 **GPU** | **服务器** | 本地无（合适的）GPU，服务器有 1 块 GB10 |
| 峰值内存 **>~19 GB** | **服务器** | 本地可用 ~19.5G 放不下；服务器统一内存 121.7G |
| **会跑超过几分钟，或吃掉本地一大块内存** | **服务器** | 占住本地机那段时间你干不了别的；它算得快不快是另一回事 |
| **带宽 / BLAS 密集**（大矩阵乘、向量化 numpy、批量指纹 / Tanimoto） | **服务器** | 统一内存带宽 1.5×、BLAS 1.2× |
| **sklearn 树模型**（RandomForest / GBM 等分支密集），**且数据小、几分钟内完** | **本地** | x86 大核打赢 ARM，实测快 ~22%；跑得久就仍上服务器 |
| 单线程轻计算（单分子指纹之类），**几秒就完** | **两边打平** | 哪方便哪跑 |

## 本机基准（i7-265K WSL2 16 核  vs  Spark GB10 20 核，2026-07-21）

| 项 | 本地 | 服务器 | 谁快 |
|---|---|---|---|
| 内存带宽 | 19.9 GB/s | 29.7 GB/s | 服务器 1.49× |
| Tanimoto（真实批量） | 0.177 s | 0.131 s | 服务器 1.35× |
| matmul (BLAS) | 643 GFLOPS | 781 GFLOPS | 服务器 1.21× |
| rdkit 指纹（单线程） | 10,366 /s | 11,134 /s | 打平 1.07× |
| **sklearn RF 拟合 + 预测** | **15.0 s/轮** | 18.3 s/轮 | **本地 1.22×** |
| 可用内存 | 19.5 GB | 121.7 GB | 服务器 6.2× |

## 为什么会这样（好对新任务泛化）

- **ARM Cortex vs x86 大核（Lion Cove）**：**分支密集 / 串行标量**代码（决策树遍历、
  大量 `if`）ARM 吃亏 → 树模型类回本地。
- **带宽 / SIMD / BLAS**：服务器统一内存带宽更高、BLAS 调优好 → 大矩阵、向量化 numpy、
  批量化学指纹类回服务器。
- **内存有两重约束**：>19G 本地根本放不下，只能服务器（哪怕它某些算子更慢）；远不到 19G 也一样 —— 本地那点内存是你的日常工作区，吃掉一大半同样是占用。
- **时长本身就是判据**：跑超过几分钟就上服务器，不管它多轻 —— 本地被占住的那段时间你干不了别的。

## 对一个"没测过"的新任务怎么判

**默认答案是服务器。** 下面每一条都是「能不能破例留在本地」的检查：

1. 要 GPU 吗？要 → 服务器。
2. 峰值内存会 >19G 吗？会 → 服务器。
3. **会跑超过几分钟、或吃掉本地一大块内存吗？** 会 → 服务器（不看它算得快不快）。
4. 主要开销是什么类型？矩阵 / 向量化 / 带宽 → 服务器；树模型 / 分支密集串行**且数据小** → 本地。
5. 都说不准 → **按默认走服务器**；真想省那趟往返，小规模两边各跑一次计时再定，别拍脑袋。
