# 执行地判定 — 本地还是上服务器？

> 在为一个任务定 slurm 参数**之前**先问：这活到底该在**本地**跑，还是上**共享服务器**？
> 上了服务器不代表更快——ARM 服务器在某些负载上反而慢。判错 = 要么白占公共资源、
> 要么把本可以更快跑完的活拖慢。
>
> ⚠️ **下面的数字是"龚宇航的本地 vs 这台 Spark"这一组基准**（2026-07-21 实测）。
> 判定**规则**（架构层面）通用；**具体数字**换一台本地机就得重标。

## 一句话判据

| 情况 | 去哪 | 为什么 |
|---|---|---|
| 要 **GPU** | **服务器** | 本地无（合适的）GPU，服务器有 1 块 GB10 |
| 峰值内存 **>~19 GB** | **服务器** | 本地可用 ~19.5G 放不下；服务器统一内存 121.7G |
| **带宽 / BLAS 密集**（大矩阵乘、向量化 numpy、批量指纹 / Tanimoto） | **服务器** | 统一内存带宽 1.5×、BLAS 1.2× |
| **sklearn 树模型**（RandomForest / GBM 等分支密集） | **本地** | x86 大核打赢 ARM，实测快 ~22% |
| 单线程轻计算（单分子指纹之类） | **两边打平** | 哪方便哪跑 |

## 本机基准（i7-265K WSL2 16 核  vs  Spark GB10 20 核，2026-07-21）

| 项 | 本地 | 服务器 | 谁快 |
|---|---|---|---|
| 内存带宽 | 19.9 GB/s | 29.7 GB/s | 服务器 1.49× |
| Tanimoto（真实批量） | 0.177 s | 0.131 s | 服务器 1.35× |
| matmul (BLAS) | 643 GFLOPS | 781 GFLOPS | 服务器 1.21× |
| rdkit 指纹（单线程） | 10,366 /s | 11,134 /s | 打平 1.07× |
| **sklearn RF 拟合 + 预测** | **15.0 s/轮** | 18.3 s/轮 | **本地 1.22×** |
| 可用内存 | 19.5 GB | 121.7 GB | 服务器 6.2× |

## 为什么会这样（好对新任务泛化）

- **ARM Cortex vs x86 大核（Lion Cove）**：**分支密集 / 串行标量**代码（决策树遍历、
  大量 `if`）ARM 吃亏 → 树模型类回本地。
- **带宽 / SIMD / BLAS**：服务器统一内存带宽更高、BLAS 调优好 → 大矩阵、向量化 numpy、
  批量化学指纹类回服务器。
- **内存是硬约束**，不是快慢问题：>19G 本地根本放不下，只能服务器（哪怕它某些算子更慢）。

## 对一个"没测过"的新任务怎么判

1. 要 GPU 吗？要 → 服务器。
2. 峰值内存会 >19G 吗？会 → 服务器。
3. 主要开销是什么类型？矩阵 / 向量化 / 带宽 → 服务器；树模型 / 分支密集串行 → 本地。
4. 三条都说不准 → 小规模两边各跑一次计时，别拍脑袋。

## 别忘了

判为服务器后，**照样走队列**（见 SKILL.md 红线）——判定只解决"去哪台机"，不豁免"必须
走 slurm 留痕"。本地跑就正常本地跑，不受这套约束。
