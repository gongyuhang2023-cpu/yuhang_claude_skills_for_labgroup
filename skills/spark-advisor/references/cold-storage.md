# 保留区：长期存数据、取回、删除

> 什么时候读：用户要把数据长期存起来（「存进保留区」「这批原始数据留一份」），要看存了什么、取回、腾掉本地、删除、挪旧归档，或者整理流程里要存东西时。整理存储的全流程在 [存储](storage.md#整理一次)。
>
> 逻辑都在服务器命令 `spark-cleanup keep` 里：以用户自己的身份运行，默认只看不动。本 skill 只转发。

目录：[是什么](#是什么) · [存进去](#存进去) · [看](#看) · [取回](#取回) · [腾本地](#腾本地) · [删除与找回](#删除与找回) · [挪旧归档](#挪旧归档) · [核对提示](#核对提示) · [不做的事](#不做的事)

## 是什么

- **每人一块**：NAS 上每人一个文件夹，路径、额度和用量都看 `keep status`（`root`、`quota`、`used`）。
- **还没开通**（`enabled` 为 false）：问用户要不要申请。同意后先预演 `keep request --note "打算存什么、大概多大"`，再加 `--yes --expect <plan_sha256>` 发出。管理员会收到邮件，开通以后 `keep status` 就有额度了。不要自己想办法开通。
- **长期保存**：不轮换。每天核对：通过本 skill 存进去的东西少了或坏了，从 NAS 快照自动补回（快照约保留 7 周）。
- **按原路径放**：`~/Workspace/Projects/X/raw` 存在 `keep/<账号>/Workspace/Projects/X/raw/`。
  - 大文件原样放：在 NAS 上能直接看到，也能只取回其中几个；
  - 小文件和 NAS 存不了的文件名，打进同一处的一个包。
  - 同一路径再存一次，新版放在 `<原路径>@<时间>`（时间取数据的修改时间），旧版本留着。
  - **软链接只存链接本身，不存它指向的数据。** 原始数据目录如果是一堆指向别处的链接，要存的是链接指向的真实数据目录；预演的 `warnings` 和 `plan.external_links` 会列出指向目录外的链接。
- **和另两处不同**：每晚备份只是后悔药；NAS 个人目录 `user/` 不限量，也没人核对。
- **只经本 skill 或 `spark-cleanup keep` 存和删。不要直接 cp、mv、rm 保留区里的文件。** 绕过去存的不算登记，不在核对范围；绕过去删掉的，会被当成误删补回来。
- **不在保留区里计算**：要用就先取回本地。

命令（路径用绝对路径，或带引号的 `'~/…'`；加 `--yes --expect` 执行时，参数要和预演时一字不差，`'~/…'` 和绝对路径算出的摘要不一样）：

    python scripts/advise.py keep status
    python scripts/advise.py keep list [--path P | --files <条目号>]
    python scripts/advise.py keep add P [--free-local] [--note "这批数据是什么"]        # 预演；加 --yes --expect <plan_sha256> 交作业
    python scripts/advise.py keep get <条目号或原路径> [--to 目录] [--only 相对路径 …]  # 预演；加 --yes --expect 交作业
    python scripts/advise.py keep free P                                              # 预演；加 --yes --expect 交作业
    python scripts/advise.py keep rm <条目号>                                          # 预演；加 --yes --expect
    python scripts/advise.py keep undelete <条目号>                                    # 预演；加 --yes
    python scripts/advise.py keep adopt [<旧归档或 NAS 路径>] [--note "…"]              # 不带路径：列出可挪的旧归档
    python scripts/advise.py keep note <条目号> "<备注>"                              # 直接改，不用预演（用户同意后再改）
    python scripts/advise.py keep job <作业号>
    python scripts/advise.py keep request [--note "打算存什么"]                         # 还没开通时请管理员开通；预演，加 --yes --expect 发邮件

## 存进去

1. **先问这批数据是什么**，比如「XX 课题的原始测序，2026-11」，写进 `--note`。备注存在服务器的登记里，跟着数据走。半年后用户说「把那个课题的原始数据拿回来」，靠它对上。备注也绑在摘要里：用户改了备注，就重新预演再执行。
2. **选存法**：
   - **留本地**（默认）：项目还在用，只是先存一份。
   - **腾本地**（`--free-local`）：项目收尾时用。核对完删本地，原处留 `<名字>.ON_NAS.txt`。
3. **预演**，把这些写进计划：存哪个目录、存到哪、大小、存完的用量（`plan.quota_after` / `plan.quota`）、预计分钟、留不留本地。`plan.git` 显示代码没推完的，先按 [代码](code-check.md) 推。
   - `plan.versions` 不为空：这个路径以前存过。旧版的 `local` 是 `same`（本地和存的一模一样）时，不用再存一份，备注不对就用 `keep note` 改；`changed` 才值得存新版，列出旧版的日期、大小和备注，问要不要顺手删旧版。
   - `plan.quota_after` 是按原始大小估的，小文件打包后实际用量会略有出入。
   - `refuse` 不为空就是不能存。照原话转告，不想办法绕过去。常见原因：超额、正在被作业或进程用、在备份计划里、点开头的目录、conda 或 pixi 环境（走 [清理](cleanup.md)）、有不属于你的文件、在 home 以外（`/scratch` 里的先挪回 home）。
   - pip 的 venv（比如 `~/boltz-env`，没有 `conda-meta`）不算环境，可以按普通目录原样存进来，取回原路径照常能用；也可以按项目里的版本清单删掉以后重建。两条路的代价（占额度，或者要重建）写给用户选。
   - `warnings` 照原话转告。里面有「交上去会先排队」，就告诉用户机器正忙：作业固定 2 核 / 8G，要等别人的作业结束才开始。
4. **执行**：用户同意后加 `--yes --expect <plan_sha256>`，提交成 Slurm 作业。断开 ssh 照常跑；同时交几个会依次排队。
   - 作业的顺序：写入 → 从 NAS 读回、逐个文件核对 → 登记 → 腾本地时再确认期间没改过、留说明、删本地。
   - 任何一步没过，本地都不动。
5. **报告**：`keep job <作业号>` 看结果。报告存到哪、多大、现在的用量；腾本地的，再报腾出多少。

预计分钟只算了 NAS 写一遍、读回一遍（约 100 MB/s），实际会长一些。

## 看

- `keep status`：额度、用量（回收站不算）、条目数、核对提示（见 [核对提示](#核对提示)）。
- `keep list`：每一项的条目号、原路径、日期、大小、备注，以及本地那份的状态 `local`：
  - `same`：本地还在，和存的一样；
  - `changed`：本地改过；
  - `absent`：本地已经没有。

  最后单列 `user/` 里的旧归档（`legacy`）。
- `keep list --path P`：查 P 或它的上层存没存过。删除计划里判断「只有这一份」，就用它。
- `keep list --files <条目号>`：列出条目里有哪些文件（相对路径、大小、原样放还是打包），只取回几个文件之前用它找路径。
- `status` 的 `last_check` 为空，说明这批数据还没经过一次每晚核对。

## 取回

- 按备注或原路径找到条目号。默认放回原路径；原处已经有东西就拒绝，不覆盖。
- 放到别处用 `--to <目录>`：东西会落在 `<目录>/<原名>/` 下，多一层原来的目录名；目录不存在会自动建。预演的 `plan.target`（带 `--only` 时是 `plan.files`）就是最终位置，照它告诉用户。
- 只要其中几个文件，用 `--only <条目内的相对路径>`，可以写多个；路径先用 `keep list --files <条目号>` 查。
- 条目的 `local` 是 `same`、本地那份还在时，用户只是要一份副本的话，直接复制更快，不用交作业，提一句。
- 作业和存入一样，固定 2 核 / 8G；本地剩余空间看 `plan.local_free`。
- 旧归档（原处有 `.ON_NAS.txt`、包在 `user/` 里的）也用 `keep get <原路径>` 搬回。
- 预演会核对本地剩余空间（不低于 `/ai.md` 规定的线）和配额。`refuse`、`warnings` 照常转告。
- 用户同意后加 `--yes --expect <plan_sha256>`，作业取回并核对。保留区那份不动。

## 腾本地

- 适用于用「留本地」存的条目（原路径），或者用 `keep get` 取回过的目录（包括旧归档）。别处的普通副本，即使内容和条目一样，`free` 也会拒绝（「没有找到 restore 记录」）；确定不要的话，按普通删除列进计划。
- `keep free P` 先核对本地和保留区那份逐个文件一致，才删本地、留说明。
- 本地改过就拒绝。这时问用户：再存一版（算新版本，占额度），还是继续留着。
- 用户同意后加 `--yes --expect <plan_sha256>`。

## 删除与找回

- `keep rm <条目号>` 先预演：列出确切条目、原路径、大小、能空出多少额度。按 [同意规则](../SKILL.md#同意规则) 逐项列出。
  - 预演的 `only_copy` 为 true，就在计划里标「只有这一份」。它只看本地原路径和别的版本，不查 `user/`、公共库和每晚备份，需要时自己补查。
  - `stub_paths` 是原处指向这个条目的说明文件。删条目不会动它们；要删的话，等删完条目再单独列进计划。说明文件也绑在摘要里，预演之后别先动它。
  - 删除和找回都是马上完成的，不交作业。
- 用户同意后加 `--yes --expect <plan_sha256>`：移进回收站，额度当场空出。
- 30 天内可以用 `keep undelete <条目号>` 找回；过了 30 天自动清掉。
- 只删用户点名的条目。整理时发现同一路径存了几版，列出来让用户选，不替用户删。
- 条目目录里有没登记的文件时，`rm` 会拒绝并列出这些文件：问用户是先登记（`keep add --register`）还是挪走，不要替用户决定。

## 挪旧归档

- `keep adopt` 不带路径：列出 NAS 个人目录 `user/` 里的旧归档和手动拷进去的目录，各有多大、原处有没有说明。旧归档指以前 `cleanup apply --action archive` 或管理员的 `nas-archive` 搬过去的东西。
- 用户选好以后，`keep adopt <路径>` 先预演：
  - 旧包：在 NAS 上换个位置，读一遍建登记，再把原处说明改成指向新位置；
  - 普通目录：打包进保留区、核对通过后，把 `user/` 里的原件移进回收站，30 天后自动清掉。这一步写在计划里，用户同意后才执行；原件里 10 分钟内有改动的会被拒绝。
- 两种都算额度。用户同意后加 `--yes --expect <plan_sha256>`。
- 预演里 `delete_source: true` 表示 `user/` 里的包会被挪走（普通目录则是移进回收站）。`new_stubs` 列出要写的新说明文件：原处已有旧说明时，旧的留着，新的写成 `<名>.keep.ON_NAS.txt`，以新的为准。
- `legacy` 里 `back_in_place: true` 表示原处又有东西了，多半是项目早已搬回来；那个旧包只是当时的快照，挪不挪进保留区问用户。
## 核对提示

`keep status` 的 `problems` 每一项有一个 `kind`，按下表讲给用户。`path` 是 NAS 上的路径，按 `keep list` 里各条目的 `path` 对回条目号再讲：

| kind | 意思 | 怎么讲、怎么做 |
|---|---|---|
| `restored` | 少了或坏了，已经从 NAS 快照补回 | 「保留区里的 X 在某天少了，已从快照补回，现在完好。」不用做什么 |
| `unrecoverable` | 快照里也找不到完好的 | 照 `detail` 原话说，建议告诉管理员；本地还有副本的，问要不要重新存 |
| `unregistered` | 保留区里有不是经本 skill 存的文件 | 「这里有 X GB 不在核对范围，要不要登记一下？」用户同意后运行 `keep add --register <NAS 路径> --yes --expect <plan_sha256>` |

## 不做的事

- 不直接改、拷、删保留区里的文件；不碰别人的保留区。
- 超额时不想办法绕，比如拆开存、改放到 `user/`；照实告诉用户那两条路：先整理保留区，或请管理员扩容。
- 不把正在算的分析、环境、`work/`、缓存放进来；不在保留区里直接计算。
- 项目刚建、分析正在跑、只是查个文件时，不提保留区。
